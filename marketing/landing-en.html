Retrospective

DOTS stopped at the warehouse door

DOTS was built for simple deliveries: one DC, one driver, one direct route. Once operations got more complex — Depots, transit legs, returns, per-leg cost — the old system had nowhere to record it.

Access

Users locked to a single Distribution Center

One account can't extend to another Depot, even when one person handles multiple locations.

Fleet

Fleet tied to a single Driver

Vehicles can't be shared across drivers within one Shipping Point.

Coverage

District coverage undefined in the system

Each DC's coverage area was known informally, never recorded on the platform.

Route

Direct shipping only

Transit through another Depot or DC happened in the field, but was never captured by the system.

Location & Coverage Area

Coverage builds itself from route data

No manual drawing of coverage areas. Map each District to the Staging Bay that handles it, and the coverage area for that Shipping Point generates itself.

Every Shipping Point has two tiers: the Distribution Center as the main warehouse, and a Depot / Cross-Dock that extends the service area. One Staging Bay can extend to another Depot once the main DC's capacity is full.

The Route Code and District on each Staging Bay are the baseline for auto-generating coverage area — their accuracy directly affects which Route Type gets auto-selected during Planning.

Added Value

Everything else that changes underneath

Smaller shifts that add up — each one removes a manual step DOTS never had a place for.

01

Centralized Transporter Config

Shipment type and shipping type mapping is set once at the Transporter level, not repeated for every Fleet.

02

Fleet as a shared resource

Vehicles are no longer tied to one Driver — they're managed and selected per Shipping Point.

03

Shipment Cost & approval

Cost is recorded per delivery leg, following a Driver → Coordinator → Cashier Admin → BCR approval flow inside the system.

04

Integrated returns

Return pick-up becomes an order type inside the same Shipment, not a separate customer-level menu.

05

More accountable login

Email & password or a Microsoft Account — accounts can no longer be freely shared between users.

06

Reason codes, managed in-app

Reason master data now includes Bahasa Indonesia translations and an active/inactive toggle, managed straight from the menu — no engineering ticket required.
